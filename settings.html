How to get a client ID

A personal Google account is enough. There is no charge, no billing to enable and no Workspace needed.

  1. Open the Google Cloud console and create or pick a project.
  2. Enable the Google Calendar API for it.
  3. Configure the consent screen (newer consoles call this Google Auth Platform). With a personal account the only available audience is External; Internal needs a Workspace organisation.
  4. Press “Publish app” so the status is “In production”. Do not leave it in Testing — see the warning below.
  5. Under Credentials, create an OAuth client ID with application type Desktop app. There is no redirect URI to fill in — a desktop client is allowed to use a loopback address, which is what Slime listens on.
  6. Paste the client ID and secret below and press Connect.
  7. Google will show an “unverified app” screen once. Choose Advanced → Go to Slime. Verification only matters for handing the app to other people; an unverified app still works for up to 100 users.

Don’t leave the app in Testing. Google revokes refresh tokens after 7 days for an External app still in Testing, so Slime would log itself out every week. Publishing to production removes that rule, and costs nothing.

Slime asks for read-only access to calendar events and nothing else. It cannot change your calendar.
